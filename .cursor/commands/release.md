# Релиз: подготовка к публикации расширения

Выполни полный цикл подготовки релиза **строго по порядку**. Не переходи к следующему шагу, пока текущий не завершён успешно (exit code 0). При ошибках — исправляй и перезапускай шаг до успеха.

## Общие правила

- Рабочая директория: корень проекта (`nmap_uploader`)
- Менеджер пакетов: `pnpm`
- Не заявляй об успехе шага без свежего вывода команды (exit code 0, 0 ошибок)
- Не пропускай шаги и не меняй порядок
- Smoke-тесты (`pnpm test:smoke`) **не запускать** — они ходят в live API Яндекса
- Коммиты и push делай **только** если пользователь явно попросит

---

## Шаг 1. Проверка актуальности тестов

Определи, нужно ли обновить тесты после недавних изменений:

1. `git status` и `git diff` — список изменённых файлов
2. Для каждого изменённого исходного файла (не теста) проверь:
   - есть ли соответствующий тест в `tests/unit/`, `tests/integration/`
   - покрывает ли тест изменённое поведение (новые функции, изменённые сигнатуры, edge cases)
3. Запусти `pnpm compile:tests` — проверка типов тестов
4. Если тесты устарели или отсутствуют — **обнови или добавь** их до запуска шага 2

**Критерий готовности:** `pnpm compile:tests` завершается с exit code 0; тесты соответствуют текущему коду.

---

## Шаг 2. Тесты

```bash
pnpm test:run
```

При падении:
1. Прочитай полный вывод ошибок
2. Исправь код или тесты (предпочитай исправление кода, если тест корректен)
3. Перезапусти `pnpm test:run`

**Критерий готовности:** все тесты проходят, 0 failed.

---

## Шаг 3. Biome (линтер и форматирование)

```bash
pnpm lint
```

При ошибках:
1. Сначала попробуй автоисправление: `pnpm lint:fix`
2. Оставшиеся ошибки исправь вручную
3. Перезапусти `pnpm lint` до чистого результата

**Критерий готовности:** `pnpm lint` — exit code 0, 0 ошибок.

---

## Шаг 4. Stylelint (CSS)

```bash
pnpm lint:css
```

При ошибках:
1. Сначала попробуй автоисправление: `pnpm lint:css:fix`
2. Оставшиеся ошибки исправь вручную в `assets/styles/**/*.css`
3. Перезапусти `pnpm lint:css` до чистого результата

**Критерий готовности:** `pnpm lint:css` — exit code 0, 0 ошибок.

---

## Шаг 5. Biome (форматирование)

```bash
pnpm format
```

Эквивалент: `biome format --write .`

После форматирования перезапусти `pnpm lint` — убедись, что форматирование не внесло новых ошибок.

**Критерий готовности:** `pnpm format` — exit code 0; `pnpm lint` по-прежнему проходит.

---

## Шаг 6. Очистка старых ZIP-архивов

Удали все `.zip` файлы в `.output/` перед новой сборкой:

```bash
find .output -name '*.zip' -type f -delete
```

Перед удалением выведи список найденных файлов (`find .output -name '*.zip' -type f`). Если `.output/` не существует — пропусти шаг.

**Критерий готовности:** в `.output/` нет файлов `*.zip`.

---

## Шаг 7. Production-сборка

```bash
pnpm build
pnpm build:firefox
```

При ошибках TypeScript или сборки — исправь и перезапусти обе команды.

**Критерий готовности:** обе команды завершаются с exit code 0.

Ожидаемые артефакты:
- `.output/chrome-mv3/`
- `.output/firefox-mv2/`

---

## Шаг 8. ZIP-архивы для публикации

```bash
pnpm zip
pnpm zip:firefox
```

**Критерий готовности:** обе команды завершаются с exit code 0.

Ожидаемые артефакты в `.output/`:
- `NmapUploader-chrome_*.zip`
- `NmapUploader-firefox_*.zip`
