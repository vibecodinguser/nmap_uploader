# 0004: Управление жизненным циклом Split View и координация вьюпорта

Контекст: кнопка разделения экрана (`goToSplitButton`) переключает режим Split View (Народная карта слева, сервис Nakarte в iframe справа). Прежняя реализация использовала нестрогий флаг `isOpen: boolean` и вызывала `notifyNmapsMapResize()` без параметров текущего местоположения. Это приводило к гонкам асинхронных операций при повторных кликах, потере слушателей при перерисовке тулбара React-деревом Яндекс.Карт и смещению центра карты из-за задержки пересчета размеров контейнера (`50vw` / `100vw`).

Решение:
1. Перевести жизненный цикл `Split View` на детерминированный конечный автомат состояний (`SplitViewStatus`: `closed` -> `opening` -> `open` -> `closing` -> `closed`) с защитой от параллельных/дребезжащих вызовов `toggleSplitView()`.
2. Явно передавать точные координаты (`location = { longitude, latitude, zoom }`) в событие `notifyNmapsMapResize(location)` при открытии и закрытии, чтобы `requestMapRepaint` в MAIN world мгновенно центрировал карту и вызывал `fitToViewport()` без рассинхрона тайлов.
3. Обеспечить идемпотентное монтирование слушателей на `goToSplitButton` с проверкой регистрационного маркера (`data-split-bound`), предотвращая утечки и дублирование при перерисовках тулбара.

Причина: гарантия целостности DOM-структуры, устранение визуального рассинхрона центров карт Nmaps и Nakarte, защита от "серых тайлов" и гонок асинхронных событий.
