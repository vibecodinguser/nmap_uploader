# 0005: Необязательный доступ к nspd.gov.ru и динамическая регистрация content scripts

Контекст: в версии 1.4.2 в `host_permissions` и `content_scripts.matches` появился домен `nspd.gov.ru`. Для браузера это новые обязательные разрешения, поэтому при обновлении расширение отключалось до подтверждения пользователя ([Chrome: Updating permissions](https://developer.chrome.com/docs/extensions/develop/concepts/permission-warnings)). Проблема повторялась на каждом апдейте, пока разрешение не принято, и стала бы постоянной при добавлении новых доменов в будущем.

Решение:
1. Объявлять доступ к НСПД необязательным: `optional_host_permissions` в MV3, `optional_permissions` в MV2 (Firefox). Перенос выполняет `moveNspdHostPermissionsToOptional` в хуке `build:manifestGenerated` — к этому моменту WXT уже добавил хосты content scripts с `registration: 'runtime'`, поэтому вычищать `host_permissions` нужно после генерации манифеста, а не в `manifest`.
2. Запрашивать доступ из действия пользователя (`permissions.request`) — при включении тумблера «Кнопка: НСПД» в настройках панели. Отказ оставляет тумблер выключенным и показывает подсказку; повторное включение снова вызывает запрос.
3. Регистрировать content scripts НСПД в рантайме через `scripting.registerContentScripts` (`lib/nspd/content_scripts.ts`) с теми же параметрами, что были в манифесте: коллектор — `document_idle`, перехватчик — `document_start` и `world: MAIN`, оба — `allFrames`.
4. Синхронизировать регистрацию с состоянием функции: при старте background, по `runtime.onInstalled` (браузер очищает динамические скрипты при обновлении), по изменению настройки в `storage.onChanged` и по `permissions.onRemoved` — при отзыве доступа скрипты снимаются, а настройка сбрасывается в `false`.

Причина: добавление функций на новых доменах больше не должно отключать расширение у существующих пользователей. Цена решения — доступ к НСПД спрашивается отдельно и только тем, кто включает функцию, а регистрация скриптов требует `scripting` (он уже запрашивался) и минимальных версий Chrome 102 / Firefox 128 для `world: MAIN` в динамических скриптах.

Примечание: `https://nspd.gov.ru/*` и `https://*.nspd.gov.ru/*` объявлены оба, хотя в Chrome и Firefox `*.nspd.gov.ru` уже покрывает апекс — набор сохранён без изменений, чтобы не менять поведение при запросе доступа.
