# 0007: Заметки — отдельная сущность со своим хранилищем

Контекст: до переделки «заметки» были надстройкой над нативным Блокнотом картографа: редактор рисовал `index.json` из папки даты на Яндекс.Диске, а расширение хранило в `storage.local` только список скрытых id и умело дорисовывать ещё не сохранённые объекты. Требования новой функции — вид фигуры (квадрат, круг), иконки, цвет, прозрачность, ширина границы, заливка и штриховка, подписи на карте, группы с перетаскиванием, поиск с фильтрами по всем заметкам сразу — в формат Блокнота картографа не помещаются: там у объекта есть только `coords`, `desc` (обрезается до 150 символов), `note_time` и `note_desc`. Кроме того, «показывать все заметки сразу» требует геометрии всех дат, а пофайловый `index.json` для этого надо скачивать целиком за каждую дату.

Решение: заметки перестают быть надстройкой над Блокнотом картографа и становятся самостоятельным доменом расширения.

1. **Разрыв связи.** Заметки не читаются из `index.json` и не пишутся в него. Объекты, загруженные через «Загрузку» (KML, GPX, GeoJSON), в панели заметок не появляются, и наоборот. Старые нативные заметки не переносятся — учёт начинается с чистого листа.
2. **Своё хранилище на том же Яндекс.Диске**, в папке приложения:
   - `notes/index.json` — Манифест заметок: атрибуты, оформление, группы и ссылки на шарды. Порядка 300 байт на заметку, то есть ~0,5 МБ на 5 000 заметок; именно этот файл читает панель при открытии;
   - `notes/geometry/<гггг-мм>.json` — Шарды геометрии по месяцам;
   - `notes/icons/<uuid>.<ext>` — пользовательские иконки отдельными файлами, не base64 внутри манифеста.
   Сохранение переписывает манифест и только затронутые шарды, а не всю геометрию.
3. **Локальный кэш в IndexedDB.** Манифест и скачанные шарды дублируются в расширении: панель открывается без сети, повторное открытие не ходит на Диск. Кэш — только ускоритель, источник истины — файлы на Диске.
4. **Рендеринг — наш.** Заметки рисует расширение своим слоем; нативные объекты редактора не трогаются вообще (прежний механизм скрытия нативных объектов по координатам больше не нужен).
5. **Скрытие объекта — режим просмотра, а не данные.** Как и раньше, оно живёт в `storage.local` и не синхронизируется между устройствами.
6. **Без офлайн-очереди.** Запись идёт в Диск с задержкой (объединение правок, сброс при закрытии панели и уходе со страницы). Без сети правки не копятся — это осознанное ограничение первой версии.

Причина: единственный способ выполнить требования — владеть форматом. Плата: заметки существуют только там, где установлено расширение, нужен собственный кэш и мерж манифеста по `updatedAt` (при правке одной и той же заметки на двух устройствах побеждает более поздняя).

Рассмотренные альтернативы: (a) держать всё в нативном `index.json` — невозможно, формат не выражает требования; (b) сайдкар к нативному `index.json` — отвергнуто вместе с решением о независимости, а также потому что «все заметки сразу» упирается в скачивание всех дат; (c) один общий файл со всей геометрией — 3–7 МБ на каждое сохранение; (d) сжатие геометрии дельтами — нечитаемый снаружи формат и сложные миграции.

Известный технический риск: штриховка полигонов предполагает `fillImageHref` в API Яндекс.Карт. Если рендерер его проигнорирует, штриховка рисуется собственным SVG-слоем. Проверяется на живой карте до реализации шага «Оформление».
