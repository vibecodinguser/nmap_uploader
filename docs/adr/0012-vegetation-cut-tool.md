# 0012: Инструмент разреза растительности

> Дополнено [ADR 0013](0013-vegetation-cut-shared-observer-and-undo.md): общий
> наблюдатель модулей НЯК и разрез одной командой с полной отменой.

Контекст: в редакторе Народной карты есть нож для строений — он режет площадь на
части. Для растительности такого инструмента нет, хотя объект устроен дробно:
контейнер `vegetation` → контур `vegetation_fc` → части `vegetation_el`, каждая
из которых открытая `LineString`. Проверка на объекте `120112714` (лесной массив,
9 частей) показала, что части стыкуются концами без зазоров: «разрез» — это не
удаление материала, а разбиение линии на части в выбранных точках.

Устройство редактора проверено в живой версии 3.548.0 и подробно описано в
`docs/nmaps-editor-internals.md`. Три факта определили решение:

1. `ymaps.geometryEditor` для объектов НЯК **не используется** — `startEditing` не
   вызывается ни при открытии, ни при рисовании. Редактор — собственная
   «активность» приложения: класс с `start`, `onStart`, `onViewAttrsRequest`,
   `stop`, `isStarted`.
2. Состояние редактор отдаёт сам через `onViewAttrsRequest()`: там `map`,
   `geoObject`, `elementRoleId`, `elementCategoryId`, `elements`,
   `geoObjectFactory`, `geometryFactory`, `onChangeElementCoords`. Это контракт
   «активность → представление», а не минифицированные внутренние поля.
3. Нативные **точки разреза** (`splitPoints`) у контурных элементов недоступны:
   редактор передаёт их только при `splittable: true`, а контурные редакторы
   такого параметра не передают. Значит, разрез нельзя свести к постановке
   маркера — нужно делить саму геометрию части.

Решение:
1. Перехватывать активности редактора, а не `ymaps.geometryEditor`. Классы
   активностей не экспортируются поимённо, поэтому хук ставится по форме
   прототипа (`start` + `onStart` + `onViewAttrsRequest` + `isStarted` + `stop`)
   через существующий `observeWebpackModules` в MAIN world на `document_start`:
   прототип оборачивается раньше, чем редактор откроет объект.
2. Читать состояние только через `onViewAttrsRequest()`, писать — только через
   отданные им обработчики (`onChangeElementCoords`) и фабрики
   (`geoObjectFactory`, `geometryFactory`). Минифицированные поля не трогаем.
3. Разрез выполнять как деление элемента на две части: первую записывать в
   исходный элемент через штатный `onChangeElementCoords` (правка идёт через
   менеджер команд, нативная отмена работает), вторую создавать как новый
   `vegetation_el` и добавлять в роль элементов контура.
4. Держать чистую геометрию отдельно (`lib/vegetation_cut/geometry.ts`).
   Попадание клика проверяется в глобальных пикселях карты (допуск 10 px), а
   точка разреза считается в географических координатах: если клик не попал в
   вершину, координата интерполируется по отрезку.
5. Отклонять вырожденные разрезы: часть из одной точки, короче метра, разрез
   ближе метра к концу линии или к границе соседней части. Иначе появляются
   обрубки, которые невозможно редактировать.
6. Ставить кнопку в нативный тулбар (`nk-button nk-button_theme_air
   nk-button_size_xl nk-on-map-toolbar__item`), после нативной кнопки разрезания,
   если она есть. Иконки ножниц в наборе `nk-icon_id_*` нет, поэтому SVG свой.
   Кнопка — переключатель режима с `aria-pressed`; Esc выключает режим.
7. Показывать инструмент только для линейной растительности (`vegetation_fc`,
   `vegetation_el`) и только в редакторе, который отдаёт `onChangeElementCoords`:
   у площадной растительности своя семантика, и там работает нативный нож.

Причина: разрезать растительность нужно тем же жестом, что и строения. Опора на
контракт активности сохраняет состояние редактора и нативную отмену, а деление
элемента соответствует тому, как устроены данные (части — отдельные объекты,
стыкующиеся концами).

Ограничения:
- Хук зависит от формы прототипа активности. Если редактор переименует методы,
  инструмент просто не включится (кнопка не появится), но ничего не сломает.
- Добавление новой части в роль элементов идёт через коллекцию
  (`getSlavesByRole(...).addGeoObject`), то есть мимо менеджера команд
  активности: отмена снимет правку первой части, но не добавление второй. Пока
  это осознанный компромисс; чтобы откат был полным, нужна команда
  `onApply`/`onUndo`, а её менеджер в `attrs` не отдаётся.
- Что сервер делает с `editContext.splitPoints` при сохранении, не проверено
  (объект при чтении `editContext` не возвращает). На решение это не влияет:
  инструмент точек разреза не использует.
