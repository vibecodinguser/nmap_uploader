# 0006: Устройство слоя инжектируемых стилей

Контекст: content scripts вставляют в страницу Народной карты собственный CSS — панель наблюдения, дропдауны ленты правок, меню геосервисов, режим раздельного вида, подавитель плашки лимита, перекраску контуров. Исторически эти стили жили в шаблонных строках TypeScript: редактор не подсвечивал их, `stylelint` проверял только `assets/styles/**/*.css`, а дубли значений (жёлтый в двух написаниях, серый текст, радиусы, стек шрифтов, палитра тёмного попапа) расходились между листами. Вдобавок `!important` было 449 штук без учёта, стили не удалялись при выгрузке расширения, а правила ряда фильтров переопределяли интерфейс хоста на любой странице ленты.

Решение:

1. **Файлы рядом с модулем.** Каждый лист — обычный `.css` в каталоге своего модуля (`lib/object_tracker/ui/styles.css`, `lib/feeds_filter/feeds_select.css`, `lib/go_to/styles.css`, `lib/go_to/split.css`, `lib/point_counter/banner_suppressor.css`). Импорт — `?inline`, то есть в бандл попадает строка, а не отдельный CSS-файл. Экспортируемые константы (`TRACKER_STYLES`, `GO_TO_STYLES`, …) сохранены: места инжекции и тесты не зависят от способа хранения.
2. **Единая точка вставки.** `lib/injected_styles.ts`: `ensureInjectedStyle(id, css)` создаёт `<style>` или обновляет текст, `removeInjectedStyle(id)` удаляет элемент. Модули не работают с `document.head` напрямую.
3. **Общий слой токенов.** `lib/injected_tokens.css` объявляет `--nmap-*` и инжектируется как `<style id="nmap-injected-tokens">` перед первым листом — автоматически, из `ensureInjectedStyle`. Отдельный от `assets/styles/theme_tokens.css`: у панели расширения другой контекст (iframe, `:host`, свои `--background`/`--foreground`), и сшивать словари нельзя.
4. **Разделение инструментов.** CSS форматирует `stylelint` (`lint:css`, `lint:css:fix`), biome форматирование CSS отключено и не считает `!important` ошибкой — иначе `biome check --write` вычистил бы защитные переопределения. Для `lib/**/*.css` разрешены id `nmap-*`, модификаторы через `_` (как у нативных `nk-*`) и хостовые классы, которые переименовать нельзя.
5. **Изоляция от хоста.** Селектор верхнего уровня обязан начинаться с `nmap-`/`#nmap-`, а хостовые классы допустимы только как точка подключения: тёмная тема редактора (`.nk-page*`), ряд фильтров (`.nk-user-events-view__filters`, обязательно с `:has(...)` по нашему контролу) и SVG карты для перекраски контуров. Инвариант закреплён тестом.
6. **Teardown.** Стили снимаются на `ctx.onInvalidated` соответствующего content script. Стиль без владельца на странице — баг, а не мелочь.
7. **Защита от регрессий.** `tests/unit/styles/` фиксирует нормализованный текст каждого листа (снапшот), бюджет `!important` по файлам, список использованных `--nmap-*` (объявлена или приходит из рантайма) и префиксы селекторов.

Причина: правка стилей должна быть дешёвой и проверяемой. Плата — ещё один тестовый каталог, снапшоты, которые надо обновлять осознанно, и требование держать `!important` в бюджете.

Что осознанно осталось вне этого слоя (известный долг):

- `lib/nspd/dom_ui.ts` собирает стили через `style.cssText` и `.style.*` (81 `!important`) — это построение DOM, а не лист;
- около 150 записей `.style.*` в `lib/feeds_filter/*`, `lib/go_to_split_view/dom.ts`, `lib/point_counter/dom_ui.ts`, `lib/panel_sidebar/dom.ts`;
- тёмная тема инжектируемых листов в Firefox: `@supports (-moz-appearance: none)` и `.browser-firefox` действуют только внутри панели расширения, до хоста не доходят;
- переменные `--nmap-feeds-popup-*`, которые пишет `lib/feeds_filter/dropdown_theme.ts`, никем не читаются — попап ленты жёстко тёмный;
- `--nmap-text-primary`, `--nmap-border`, `--nmap-text-secondary` используются в `assets/styles/uploader.css` и `components/NoteListItem.tsx`, но нигде не объявлены;
- сам `assets/styles/uploader.css` (1758 строк) — другой контекст и отдельная задача.
