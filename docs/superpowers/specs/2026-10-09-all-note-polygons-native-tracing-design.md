# Автоматическая трассировка по всем полигонам выбранной даты

## Цель

Убрать ручной выбор одного полигона для трассировки. Пока пользователь отдельно включает штатную функцию НЯК «Трассировка», целями автоматически становятся все валидные полигональные заметки выбранной в панели даты.

## Пользовательское поведение

- В списке заметок отсутствует состояние выбранной цели и специальная подсветка строки.
- Обычный клик по заметке только раскрывает или сворачивает её.
- Все полигоны выбранной даты доступны штатной трассировке без дополнительного действия.
- Точки, линии и некорректные полигоны не участвуют в трассировке.
- Смена даты немедленно заменяет набор целей.
- Добавление, редактирование и удаление заметки немедленно обновляет набор целей.
- При выключенной штатной «Трассировке» заметки не влияют на рисование.

Полигоны других дат не участвуют, даже если ранее отображались или трассировались.

## Контракт данных

`DrawMapObjectsDetail` заменяет одиночное поле:

```ts
snapTarget: PolygonSnapTarget | null
```

на:

```ts
snapTargets: PolygonSnapTarget[]
```

`createPolygonSnapTargets(points)` фильтрует только `geomType === 'Polygon'`, требует строковый `id` или `localId`, нормализует и замыкает контур. Некорректная заметка пропускается независимо от остальных.

Панель формирует `snapTargets` из уже отфильтрованного массива заметок выбранной даты. Полный массив проходит без изменения смысла через background relay и panel-sidebar bridge в MAIN world.

Парсер MAIN world принимает только массив. Некорректные элементы пропускаются; отсутствие или неверный тип `snapTargets` трактуется как пустой набор. Обратная совместимость с одиночным `snapTarget` не требуется, поскольку все части расширения обновляются одной сборкой.

## Интерфейс панели

Из `NotesTab` удаляются:

- `activeSnapNoteId`;
- `activateSnapTarget`;
- `isSnapTarget` и `aria-pressed`;
- класс `notes-list-item-btn--snap-target`;
- логика сброса выбранной цели при удалении и смене даты.

Из `assets/styles/uploader.css` удаляется неиспользуемый стиль выбранной цели.

Раскрытие заметки, редактирование, удаление и остальные действия не меняются.

## Адаптер штатной трассировки

Интерфейс адаптера становится:

```ts
setTargets(targets: PolygonSnapTarget[]): void
```

Для каждой цели создаётся отдельная нативная Polygon-геометрия с исходными вершинами. Адаптер не добавляет проекции курсора или иные промежуточные вершины.

При вызове штатного tracer-provider адаптер:

1. проверяет расстояние от курсора до границы каждой цели в экранных координатах;
2. отбирает цели в пределах штатного `hotspotWidth`;
3. выбирает ближайшую; при равном расстоянии сохраняет порядок payload;
4. добавляет в исходный результат provider ровно один transient candidate, если такого ID ещё нет.

Такой выбор не увеличивает число кандидатов пропорционально числу заметок и сохраняет предсказуемое поведение при пересечении полигонов.

Transient candidate остаётся замороженным read-only объектом и не регистрируется в geoObjects карты, editor state, undo/redo или save payload. Служебный ID имеет вид `nmap-uploader:note:<id>`.

## Отказоустойчивость

- Пустой набор целей возвращает только штатные кандидаты.
- Ошибка геометрии одной заметки исключает только её.
- Ошибка capability probe восстанавливает оригинальный provider и отключает интеграцию целиком.
- Повторная доставка одинакового массива не создаёт дубликаты.
- `destroy()` очищает весь набор и восстанавливает внутренние методы НЯК.
- Диагностика не содержит координаты или данные заметок.

## Тестирование

Unit-тесты проверяют:

- построение целей из всех и только полигонов выбранной даты;
- нормализацию каждого контура и пропуск некорректных элементов;
- сериализацию и парсинг `snapTargets`;
- выбор ближайшего полигона;
- стабильное разрешение равных расстояний;
- добавление только одного transient candidate;
- отсутствие промежуточных вершин;
- замену и очистку полного набора;
- восстановление provider при `destroy()`.

Тесты `NotesTab` проверяют отсутствие ручного состояния выбора и автоматическую отправку всех полигонов текущей даты. Интеграционный тест проверяет доставку массива до MAIN-world адаптера.

Ручная проверка в живом НЯК:

1. создать или открыть дату с двумя полигональными заметками;
2. не выбирать отдельную заметку;
3. начать рисование растительности и включить штатную «Трассировка»;
4. последовательно протрассировать границы обоих полигонов;
5. убедиться, что в результате присутствуют только исходные вершины;
6. сменить дату и убедиться, что старые полигоны больше не участвуют.

## Критерий готовности

Без ручного выбора доступны все полигоны выбранной даты; ближайший к курсору полигон трассируется штатным интерфейсом НЯК без дополнительных вершин и без попадания заметок в модель сохранения.
