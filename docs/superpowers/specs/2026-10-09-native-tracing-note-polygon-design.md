# Штатная трассировка по полигону заметки

## Цель

Сделать выбранный полигон из Блокнота картографа полноценной временной целью штатной функции «Трассировка» в редакторе Народной карты.

Эта спецификация заменяет DOM-подход из `2026-10-08-polygon-note-snapping-design.md`: расширение больше не подменяет координаты событий мыши и не рисует собственный маркер snapping.

## Пользовательское поведение

- Пользователь выбирает одну полигональную заметку в панели расширения.
- Пользователь самостоятельно включает штатную кнопку «Трассировка» в редакторе НЯК.
- Пока трассировка включена, контур выбранной заметки участвует в ней наравне с обычными объектами карты.
- Подсветка цели, snapping, выбор направления и добавление участка границы выполняются штатным интерфейсом НЯК.
- При выключенной трассировке выбранная заметка остаётся видимой, но не влияет на обычное рисование.
- Выбор другой полигональной заметки немедленно заменяет цель.
- Выбор точки или линии, смена даты, удаление активной заметки и закрытие страницы удаляют цель трассировки.

## Ограничения безопасности

Временная цель:

- доступна только подсистеме трассировки;
- является read-only;
- не добавляется в модель редактируемого или создаваемого объекта;
- не попадает в команды сохранения, отмены и историю изменений НЯК;
- имеет служебный ID с пространством имён расширения;
- удаляется при деактивации и повторной инициализации.

Если эти свойства невозможно подтвердить для текущей версии редактора, адаптер не включает функцию.

## Архитектура

### Выбор цели

Существующее состояние активной заметки в `NotesTab` и payload `snapTarget` сохраняются. Payload содержит только служебный ID и валидный замкнутый контур в координатах `[longitude, latitude]`.

### Адаптер штатной трассировки

В `MAIN world` устанавливается отдельный адаптер, не зависящий от React и DOM панели. Он:

1. получает и хранит текущий `snapTarget`;
2. отслеживает состояние штатной функции «Трассировка»;
3. обнаруживает источник кандидатов трассировки через capability probe;
4. добавляет временный read-only feature в результат поставщика кандидатов;
5. удаляет feature при смене цели, выключении трассировки или уничтожении адаптера.

Интеграция выполняется на границе поставщика кандидатов, а не через DOM-события указателя. Исходный результат поставщика сохраняется без изменений; временная цель добавляется только один раз и только при активной трассировке.

### Обнаружение внутреннего API

Имена внутренних модулей НЯК могут меняться. Адаптер проверяет поведение объекта, а не полагается только на обфусцированное имя:

- поставщик возвращает коллекцию геометрических кандидатов;
- кандидат содержит ID и линейную или полигональную геометрию;
- вызов происходит при включении штатной трассировки;
- добавленный тестовый feature доступен hit-test трассировщика;
- feature отсутствует в модели сохраняемого объекта.

Результат capability probe кэшируется на время жизни страницы. Повторная инициализация сначала восстанавливает оригинальные методы.

### Резервный режим

Если поставщик кандидатов нельзя расширить напрямую, допускается временный объект-клон только при выполнении двух проверок:

1. штатный трассировщик видит клон;
2. клон отсутствует в редактируемой модели и payload сохранения.

Клон добавляется в отдельную коллекцию без интерактивности, редактирования и собственного отображения. При невозможности доказать обе проверки резервный режим не используется.

## Удаляемый подход

Из `nmaps_polygon_snap_controller` удаляются:

- capture-обработчики `pointermove`, `pointerdown`, `mousedown`, `mousemove` и `click`;
- подмена `clientX`, `clientY`, `pageX` и `pageY`;
- модификация getter-ов `MouseEvent.prototype`;
- собственный синий маркер;
- экранная геометрия с порогом 10 px.

Чистый модуль экранной геометрии удаляется, если после перехода на штатную трассировку у него не останется потребителей.

## Отказоустойчивость

- Ошибка capability probe отключает интеграцию и не мешает штатному рисованию.
- Исключение внутреннего API восстанавливает оригинальный поставщик кандидатов.
- Некорректный или незамкнутый контур не регистрируется.
- Повторная доставка payload не создаёт дубликаты.
- Диагностика использует префикс `[nmap_uploader] native tracing` и не содержит координаты или данные пользователя.

## Тестирование

Unit-тесты с контрактным fake-provider проверяют:

- цель добавляется только при активной штатной трассировке;
- исходные кандидаты сохраняются и не изменяются;
- цель добавляется ровно один раз;
- смена и сброс цели удаляют старый feature;
- `destroy()` восстанавливает исходный provider;
- некорректная capability отключает адаптер;
- временный feature помечен как read-only и не входит в сохраняемую модель.

Интеграционные тесты проверяют доставку `snapTarget` из панели в адаптер и отсутствие старых обработчиков DOM-событий.

Ручная проверка в актуальном НЯК обязательна:

1. выбрать полигональную заметку;
2. начать создание растительности;
3. отдельно включить штатную «Трассировку»;
4. построить участок по границе заметки в обоих направлениях;
5. завершить и сохранить объект;
6. убедиться, что заметка не стала объектом НЯК и не попала в историю изменений;
7. повторить выключение трассировки, смену заметки, смену даты и отмену рисования.

## Критерий готовности

Функция считается готовой только после успешной ручной проверки в живом редакторе. Прохождение unit-тестов без подтверждения нативного hit-test недостаточно.
